# Rollups and query planning

Rollups pre-aggregate recurring questions so reports read summary rows instead of replaying every event. Query plans show when those summaries can answer a request.

## Follow a report's plan

The planner considers the dimensions used by grouping, event filters, and conditional metrics, as well as the requested aggregates and historical coverage.

It can read daily summaries for aligned days, hourly or minute summaries for finer portions, and event history where aggregate coverage is unsuitable. A request can combine sources.

| Plan signal | Meaning |
| --- | --- |
| UsedRollups | A configured aggregate tier contributed |
| UsedRawEvents | Event-level data contributed |
| UsedDimensionIndexes | An ordered copy narrowed raw reads |
| UsedRollupIndexes | A covering equality index read aggregate rows |
| Warnings | A condition affects coverage or interpretation |
| Notices | Temporary source fallback during background index work |

Each step names an event, a time range, and a source. Indexed steps also identify the equality dimension.

## Explain slow filtered reports

An unfiltered report may read a few summary rows. Adding a filter can require a different joint combination and much more event-level work.

| Report | Required stored dimension set | Selective rollup-index leader |
| --- | --- | --- |
| Group by source | source | Usually unnecessary for this unfiltered report |
| Filter source, group by country | source + country | source |
| Filter country, group by source | source + country | country |
| Filter page, group by source | page + source | page |

The two middle reports share an aggregate combination but need different leading keys for selective equality reads. Session and goal metrics can add separate plan steps with their own requirements.

Dimension indexes narrow matching events. [Rollup indexes](../secondary-indexes/secondary-indexes.mdx) provide an ordered aggregate path for explicitly selected equality filters. Choose the approach from the report's plan rather than its displayed row count.

Coverage also depends on activation dates, retention, and enabled time tiers. Enabling an index cannot recover expired raw history.
